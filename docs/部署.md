# 自托管部署指南

这个项目**不租云服务器**：跑在你自己电脑上，手机通过 Tailscale 在任何网络下访问。
理由写在 README 的「已知取舍」里——个人作品集是私用工具，别人拿走应该是空库，没有对外提供服务的需求。

下面是从一台干净的 Windows 电脑把服务跑起来、以及日常维护的完整流程。

---

## 一、前置条件

| 需要 | 说明 | 检查命令 |
| --- | --- | --- |
| Windows 10/11 + PowerShell 5.1 | 系统自带 | `$PSVersionTable.PSVersion` |
| Docker Desktop | 引擎要能起来（WSL2 后端） | `docker info` |
| 三个 API 密钥 | DeepSeek（对话）、SiliconFlow（向量）、GPT（图片描述） | 见 `.env.example` |
| Tailscale（可选） | 只有"手机在任何网络下访问"才需要 | `tailscale status` |

> 不需要装 Python、Node、JDK——这些东西全在镜像里。手机 App 才需要 JDK（见 README 的安卓章节）。

---

## 二、三步跑起来

```powershell
# 1. 拿代码
git clone https://github.com/Jeno-Ra/portfolio-hub.git
cd portfolio-hub

# 2. 配密钥（.env 已在 .gitignore 里，不会被提交）
Copy-Item .env.example .env
notepad .env      # 填 DEEPSEEK_API_KEY / EMBEDDING_API_KEY / GPT_API_KEY

# 3. 一键部署
.\scripts\deploy.ps1
```

如果 PowerShell 拦脚本，先放开当前会话的执行策略：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

脚本跑完会打印三个地址：

```
本机        http://127.0.0.1:8000
Tailscale   http://100.x.x.x:8000     （手机任何网络都能用）
局域网      http://10.x.x.x:8000      （同一 WiFi 下）
```

---

## 三、脚本到底做了什么

`scripts/deploy.ps1` 不是简单的一句 `docker compose up`，每一步都先检查再动手：

| 步骤 | 做什么 | 失败时 |
| --- | --- | --- |
| 1 | 找 `docker` 命令，查引擎是否在跑；没跑就启动 Docker Desktop 并最多等 90 秒 | 提示去装 Docker / 手动打开 Docker 看报错 |
| 2 | 检查 `.env`；没有就从 `.env.example` 复制一份 | **停下来**，让你填密钥（而不是让容器起来后报 502） |
| 3 | 检查三个密钥是否为空 | 列出空的是哪几个 |
| 4 | `docker compose up -d --build` | 自动打印 backend 最近 50 行日志 |
| 5 | 轮询 `/health` 直到真的返回 `{"status":"ok"}`（默认最多 120 秒） | 打印日志，提示手动看 `docker compose logs -f backend` |
| 6 | 打印本机 / Tailscale / 局域网三种地址 + 容器状态表 | — |

两个常用参数：

```powershell
.\scripts\deploy.ps1 -NoStart     # 只做环境检查，不启动（改密钥前先自查）
.\scripts\deploy.ps1 -SkipBuild   # 不重建镜像，直接用现有镜像启动（快）
```

### 实测数据（本机）

| 场景 | 耗时 |
| --- | --- |
| 容器全停，脚本重新建容器（镜像不重建） | **15.7 秒**（其中后端健康 6.2 秒） |
| Docker Desktop 也关了，脚本自动拉起 | **32.8 秒**（引擎约 20 秒 + 后端 6.2 秒） |
| 服务已经在跑，再跑一次脚本 | 约 2 秒（直接通过健康检查） |

## 四、数据存在哪

三个命名卷，`docker compose down` **不会**删它们：

| 卷 | 内容 | 丢了会怎样 |
| --- | --- | --- |
| `portfolio_appdata` | 上传的原件 `media/` + SQLite 时代的旧库（现在走 Postgres，这个库只在无 `DATABASE_URL` 时用） | 拖进来的文件全没 |
| `portfolio_pgdata` | Postgres 数据库（作品、切片、会话、标签） | 所有作品和对话记录全没 |
| `portfolio_chromadata` | 向量库 | 可以从 Postgres 重建（重新录入即可） |

查看卷的真实位置：

```powershell
docker volume inspect portfolio_pgdata --format "{{.Mountpoint}}"
```

> `docker compose down -v` 会删卷，等于清库。只在"我要从零开始"时才用。

## 五、备份与恢复

**备份**（建议每周一次，或改完一批作品后）：

```powershell
$stamp = Get-Date -Format "yyyyMMdd-HHmm"
docker compose exec -T postgres pg_dump -U portfolio portfolio > "_backup-$stamp.sql"
docker run --rm -v portfolio_appdata:/data -v ${PWD}:/backup alpine tar czf "/backup/media-$stamp.tar.gz" -C /data media
```

**恢复**：

```powershell
docker compose up -d postgres
Get-Content .\_backup-20261123-1400.sql | docker compose exec -T postgres psql -U portfolio -d portfolio
docker run --rm -v portfolio_appdata:/data -v ${PWD}:/backup alpine tar xzf "/backup/media-20261123-1400.tar.gz" -C /data
```

向量库不用单独备份：它的内容完全由 Postgres 里的作品正文生成，真丢了把作品重新走一遍索引即可。

## 六、日常操作

```powershell
# 改了代码要上线
git pull
.\scripts\deploy.ps1              # 会自动 --build

# 只是重启
docker compose restart backend

# 停服务（数据不动）
docker compose stop

# 看日志
docker compose logs -f backend

# 完全移除容器（数据仍留）
docker compose down
```

桌面客户端（`desktop\启动作品集.ps1`）会自己检查后端、必要时启动 Docker，所以日常其实不用记这些命令——双击图标就行。

## 七、换一台机器 / 给朋友

代码可以直接共享，**但这四样东西各自独立，不要一起外发**：

- `.env`（你的密钥）
- `portfolio_pgdata` / `portfolio_appdata` 卷（你的作品）
- Tailscale 设备（你的网络）
- `mobile/dist/作品集-手机安装.apk` 里写死的 Tailscale 地址（指向你的电脑）

别人拿到仓库后照第二节做，`deploy.ps1` 会给他一个空库；他的 Tailscale 地址不同，手机 App 要自己重编（`npm run build:apk`）。

## 八、故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `deploy.ps1` 报"这些密钥是空的" | `.env` 没填或填在引号里 | 直接改 `.env`，值不要加引号 |
| 脚本说后端就绪，但浏览器打不开 | 8000 被别的进程占了 | `Get-NetTCPConnection -LocalPort 8000 -State Listen`，先停掉占用者 |
| `/health` 有响应但页面是旧的 | Docker Desktop 没重启，旧容器还在 | `docker compose up -d --build` |
| 容器起来就退出，日志报 `PermissionError: '/app/data'` | 卷属主不是 appuser | `docker run --rm -v portfolio_appdata:/data alpine chown -R 10001:10001 /data` |
| 后端启动很慢（>60 秒） | 同时开了 RAGFlow 那套（ES 很吃内存） | `docker compose -p ragflow stop`，本项目常驻只要约 190 MB |
| 手机连不上，但本机能开 | 手机 Tailscale 没开 / 不在同一 tailnet | 手机打开 Tailscale，`tailscale status` 看两台设备是否都 `active` |
| 手机打开只有"连不上服务器"兜底页 | 电脑上的 Docker 没启动 | 电脑双击桌面「作品集」图标（它会拉起 Docker），手机再重开 App |

## 九、安全说明

- **只暴露 8000 一个端口**：Postgres 和 Chroma 不映射到宿主机，只在 compose 内部网络里互相访问。
- **不出公网**：Tailscale 是加密的点对点组网，没有对外的公开入口；没有做端口映射，也不需要令牌（对比 Cloudflare Tunnel 那种方案必须先加鉴权）。
- **密钥只在 `.env`**：`.env` 在 `.gitignore` 里；镜像构建时 `.dockerignore` 排除了它，容器里读的是挂载进环境变量的值，镜像里没有密钥副本。
- **AI 只能改元信息**：`backend/app/policy.py` 硬拦 `content` / `source_path`，删除作品时只删上传副本（`media/` 里的那份），不碰你原始文件。
