# 评测

两个文件 + 一个脚本，用来量化检索质量。

| 文件 | 作用 |
|---|---|
| `corpus.json` | 评测语料（作品列表）。**目前是合成数据** |
| `questions.json` | 50 条评测集，五类各 10 条 |
| `run_eval.py` | 录入语料 → 建索引 → 逐条检索 → 统计 → 清理 |

## 运行

```bash
uv run python eval/run_eval.py
```

脚本会自己录入语料、**跑完删掉自己录入的作品**（按 id 精确清理），不碰你库里的真实数据。

## 指标

| 指标 | 含义 |
|---|---|
| `recall@5` | 该命中的问题里，正确答案出现在 top-5 的比例 |
| `拒绝准确率` | 该拒绝的问题里，过滤后结果为空的比例（距离全部 > 阈值） |
| 检索平均耗时 / p95 | 向量检索本身（embed 问题 + Chroma 查询），不含大模型生成 |

生成阶段的首字延迟不在这里测，用 `/ask/stream` 单独测（见补课日历的执行记录）。

## 五类问题

| 类型 | 数量 | 检验什么 |
|---|---|---|
| 事实型 | 10 | 能不能找到对应作品 |
| 细节型 | 10 | 能不能命中埋在正文里的具体数字 |
| 多作品 | 10 | 一个问题涉及 2 条作品时，能不能都召回 |
| 口语同义 | 10 | 不出现作品名、用生活化说法时还能不能找到 |
| 应拒绝 | 10 | 库里没有相关内容时，会不会硬凑答案 |

## 换成真实数据

`corpus.json` 现在是合成数据，**跑出的 1.00 只能证明链路和阈值是通的，不能写进简历**。
换成自己的作品后重跑，那个数字才是真的：

1. 把 `corpus.json` 的 `works` 换成你的真实作品（title / type / tags / content）
2. 按你的作品改写 `questions.json`，`expected` 填真实存在的标题，`expected: []` 表示"库里应该没有"
3. 重跑

**`expected` 必须由你判断**——"这条问题该命中哪几条作品"是主观标准，别人给你编的评测集，测出来的不是你的系统质量。
